Erster Release. meetingsync wandelt MacWhisper-Exporte über ein lokales Modell in LM Studio in eine Meeting-Notiz mit Tasks und Projekt-Verknüpfung in Notion um. Alles läuft auf dem Mac, das Rohtranskript verlässt ihn nicht (Ausnahme: `include_transcript`).

## Funktionen

- Erkennt Transkript und Zusammenfassung an Endung und Inhalt (`.srt`/`.vtt` immer Transkript).
- Bildet Paare aus Transkript und Zusammenfassung (gleicher Namensstamm, sonst zeitlich nächste Datei).
- Liest das Datum aus dem Dateinamen (MacWhisper-Format und `TT.MM.JJJJ`).
- Verdichtet lange Transkripte abschnittsweise (Chunking).
- Legt in Notion eine Notiz (Notes), Tasks und die Zuordnung zu einem aktiven Projekt an.
- Archiviert nach `_archiv/JJJJ-MM`; ein Ledger verhindert Doppelverarbeitung.
- Retry mit Backoff, nach `max_attempts` (Standard 10) landet die Datei in `_fehler`.
- `-dry-run`, `-check` und `-once` zum Testen.
- Config als YAML (bestehende JSON-Config funktioniert weiter).
- Notion-Token aus dem Schlüsselbund.
- Dauerbetrieb per launchd.

## Voraussetzungen

- macOS und Go 1.22+
- LM Studio mit geladenem Modell (getestet: `google/gemma-4-31b-qat`, Kontextlänge mind. 32768)
- Notion-Integration, verbunden mit der Second-Brain-Seite
- MacWhisper

## Installation

Es gibt keine Binaries, gebaut wird aus dem Quellcode:

```bash
git clone https://github.com/bmark86/meetingsync.git && cd meetingsync
go build -o ~/bin/meetingsync .
mkdir -p ~/.config/meetingsync && cp config.example.yaml ~/.config/meetingsync/config.yaml
~/bin/meetingsync -check   # oder meetingsync, wenn ~/bin im PATH liegt
```

Token im Schlüsselbund, Config-Werte, LM-Studio-Einstellungen und launchd: siehe README, Abschnitt "Einrichtung".

## MacWhisper-Export

Empfohlen ist die kombinierte `.srt` (Sprecher + Zeitmarken). Setze `my_speaker_label` auf `"Microphone"`.

## Bekannte Einschränkungen

- `meetingsync -check` endet mit Exit 0, auch wenn ein Punkt ✗ zeigt (z. B. LM Studio). Ausgabe lesen.
- `-file` ohne `-dry-run` schreibt keinen Ledger-Eintrag und verschiebt die Datei nicht. Liegt sie im `watch_dir`, entsteht beim nächsten Lauf eine zweite Notiz.
- Ist LM Studio länger aus, als `max_attempts` erlaubt (bei den Standardwerten ca. 95 Minuten), landen die Dateien in `_fehler` und müssen von Hand zurück in den Exportordner.
- Die Fehlerzähler sind nicht persistent.
- Fehlermeldungen zu `orphan_summary_action` und `timezone` geben den Wert aus (`%q`).
- Mit Go 1.26.10 oder neuer bauen; ältere Toolchains haben bekannte Schwachstellen in der Standardbibliothek (u. a. crypto/tls, net/http).

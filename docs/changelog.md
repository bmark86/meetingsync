### Fixed
- R-M3-18: a failed move to `_fehler` keeps the attempt count (state kept, retry in 2 min). After `max_attempts` the next try moves the files without an LLM run, so no Notion page is created; changed content counts as a new file. Log `max_attempts erreicht, neuer Versuch, die Dateien nach <dir> zu verschieben`. Partner is moved before the transcript in the interrupted, giveUp and block-cap paths. See progress item 19.
- R-M3-20 ⚠: a German date followed by `_`, `-` or `.` and a time (`07.01.2026_08-45`) is no longer read as ISO date; the German date is used when it starts before the ISO match. `DD.MM.YYYY_HH-MM` and `_HH.MM` now give 2026-01-07 08:45 (was estimate, or wrong 2026-08-15 for `_08-15`); `DD.MM.YYYY.HH.MM` gives the date only. Other name patterns unchanged. Golden unchanged. See progress follow-up 22.
- R-M1-07 ⚠: a failed archive move (`moveFile` error, e.g. `Remove(src)`) is retried after 2 min via the retry state, on all archive paths; the warning `… konnte nicht archiviert werden …` and the copy no longer repeat every poll. Not counted against `max_attempts`, never sends the file to `_fehler`; state cleared on success. In `Pass` the summary retry gate now runs before `HasNear`. Golden unchanged. See ADR 0004.
- R-M1-07 ⚠: `listEntries` skips non-regular files (symlinks, FIFOs, devices), logged once per path: `<name>: keine reguläre Datei (z. B. Symlink) → übersprungen`. Fixes a hang: a FIFO with a supported extension blocked `ReadFile`. Visible change: symlinks in the export folder are no longer processed.
- R-M1-07: a failed folder fsync on the target volume after a synced copy is a warning (`Zielordner nicht synchronisiert, trotzdem verschoben nach …`), the move continues; also for `_fehler` (`.fehler.txt` still written). Decided by Mark, 2026-11-02. See ADR 0005.
- R-M1-05 ⚠: TOCTOU recheck before archiving (S-15). `archiveJob` compares size and mtime of the job's primary file (`Lstat`) with the values from `listEntries`; if changed, the file stays in the export folder with the warning `<Datei> wurde seit dem Einlesen geändert → nicht archiviert, bleibt im Exportordner (nächster Durchlauf prüft sie erneut)`. Partners are archived as before; `fertig` is still written. Applies to the processed and the already-processed (`Has`) path; no recheck in `-dry-run`, `HasNear` and orphan paths. Behavior change: a transcript changed during processing gets its own note in the next pass (without the summary as context); the first note stays. Before, the changed file was archived and its new content never processed. Golden unchanged. See ADR 0004.
- R-M1-04: `moveFile` never overwrites an existing target: same volume uses `unix.RenamexNp` with `RENAME_EXCL` (on `EEXIST` the next name `stem (n).ext`). On `EXDEV`/`ENOTSUP` the copy fallback checks the source (regular file, same identity, symlinks refused), copies with `O_CREATE|O_EXCL`, syncs file and target folder, and checks identity before `Remove(src)`. Other rename errors are returned.
- R-M1-04: no accumulating copies. If `Remove(src)` fails, only meetingsync's own fresh copy is deleted (identity-checked), the original stays, with a warning. A partial copy after an `io.Copy`/`Sync`/`Close` error is deleted too (own copy only). Both deletions approved by Mark. After a folder fsync error or an identity mismatch both files stay.
- R-M1-04: `.fehler.txt` is created with `O_EXCL` (next name on conflict); write errors are logged (`Fehlerhinweis zu <name> nicht geschrieben: …`).
- R-M1-02: restart rule: a file whose last ledger status is `begonnen` goes to `_fehler` (partner first, primary last) with a `.fehler.txt` note to check Notion, log line `letzter Lauf wurde beim Anlegen in Notion unterbrochen`, then `verworfen`; identical copies in the same pass follow. ### Security
- R-M4-01: real Notion data source IDs removed from `config.example.yaml` and `config.example.json` (placeholder `00000000-0000-0000-0000-000000000000`); README asks users to enter their own IDs. The IDs remain in git history until R-M4-02 (S-05, A-20).
- R-M3-15 ⚠: `llm.api_key` can come from the Keychain (S-18, D9). Order: env `LLM_API_KEY` -> Keychain if `llm.api_key_keychain_service` is set -> `llm.api_key`. A Keychain error aborts start (also `-dry-run` and `-check`; `-check` prints no check line then) with `LLM-API-Key aus dem Schlüsselbund (<dienst>) nicht lesbar: <exit status>`. Without a key no `Authorization` header is sent (request and golden unchanged); the header goes only to the loopback base URL. The key never appears in logs or errors. `internal/secret` shares one `source` type with the Notion token (behaviour unchanged). `config.example.*` document the new key. See ADR 0014.
- R-M3-08: IDs in the Notion paths `/v1/databases/{id}`, `/v1/data_sources/{id}`, `/v1/data_sources/{id}/query` and `/v1/blocks/{id}/children` are escaped with `url.PathEscape` (S-16). Valid UUIDs give the same path; `/`, `?` and `#` stay inside one path segment. Accepted residual risk (OD-12): `.` and `..` are not escaped, so a config value `..` could be normalized by a server or proxy; only the user's own config can set it.
- R-M3-04: new ledger file, `.fehler.txt` and copy-fallback copies are created 0600; new folders (archive root, `_fehler`, month folders) 0700, set explicitly after creation, independent of umask (S-12, OD-10 new items only). Existing files and folders keep their mode, nothing is chmod'ed; an atomically renamed export file keeps its mode (e.g. 0644). Ledger `Add` detects a new file via `O_EXCL`; fsync of file and folder unchanged. `mkdirPrivate` (Mkdir 0700 + Chmod per missing level) exists in `internal/ledger` and `internal/watch` because of import rules. gosec G301/G302/G306 exclusions now only for `_test.go`. Tests with umask 0 and 0277 catch every removed Chmod. Golden unchanged. Residual: Chmod follows symlinks between Mkdir and Chmod (parent folders are Mark's own).
- R-M3-03/R-M3-19: export files are opened with `O_NOFOLLOW|O_NONBLOCK`, must be regular files (`fstat`) and are read up to 20 MB (S-04). A symlink swapped in after listing is refused (ELOOP), a FIFO or folder gives `keine reguläre Datei` without a hang. The copy-fallback source is opened the same way. `-file` still follows a user-given symlink. gosec G304 path exclusion removed; remaining opens carry line-level `nolint` with a reason.
- R-M3-07: `internal/notify` runs `/usr/bin/osascript` and `internal/secret` runs `/usr/bin/security` by absolute path (constants, no PATH lookup; S-10). Both start with an explicit minimal environment: `HOME`, `USER`, `LANG` (each only if set) and `PATH=/usr/bin:/bin`; `NOTION_TOKEN`, proxy variables, `TMPDIR`, `SHELL`, `LOGNAME` etc. are not passed. Arguments, osascript escaping, output trimming and error texts unchanged. gosec G204 exclusion removed from `.golangci.yml`; the two `exec.Command` lines carry a line-level `//nolint:gosec` with reason. `minimalEnv` is duplicated in both packages (a shared package would need an arch rule change). Tests assert exact path and environment and cannot start the real binaries. Golden unchanged.
- R-M3-02 ⚠: start aborts unless `notion.base_url` has scheme https (http only for exact loopback `localhost`, `127.0.0.1`, `::1`), no userinfo and a host (S-03); messages without the value. `llm.base_url` and `notion.base_url` also reject a query or fragment (`?`, `#`). The Notion client does not follow redirects (3xx is a non-transient error `Weiterleitung wird nicht verfolgt`); proxy stays allowed. New `domain.RedactURL`; `-check` and `LM Studio nicht erreichbar unter …` print the LM Studio address without path (`http://localhost:1234`, golden G10b one line, approved by Mark). Residual: wrapped `url.Error` keeps the request path (no credentials) in the local log. See ADR 0008.
- R-M3-01 ⚠: start aborts unless `llm.base_url` has scheme http/https, no userinfo and host exactly `localhost` (lowercase), `127.0.0.1` or `::1` (S-02, D3); message `llm.base_url muss auf diesen Mac zeigen (localhost, 127.0.0.1 oder ::1)` without the URL. The LLM client uses no proxy and does not follow redirects (a 3xx is a non-transient error), so the transcript cannot leave via proxy or 307. Residual risk: `/etc/hosts`. See ADR 0007.

A 2xx over the limit or with a read error is an error without body content (non-transient); error statuses are read with the same limit and the status still decides (transient classes unchanged). `llm` `Models()` returns `LM Studio /models: HTTP <n>` for status >= 300, so `-check` shows `✗ LM Studio nicht erreichbar unter …` instead of an empty model list (exit code and golden unchanged). New `notion.ErrUnklar` wraps an incomplete 2xx read of `CreatePage` (page may exist; treated as non-transient until R-M3-17). A truncated PATCH reply when appending blocks counts as append error (`ErrUnvollstaendig`, warning). S-08, A-15.
